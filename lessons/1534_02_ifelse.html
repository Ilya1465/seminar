{% section "Зачем нужны условия" %}

Все программы, которые мы писали до сих пор, имели линейную структуру: каждая инструкция выполнялась одна за другой, по порядку. Такая программа умеет только одно — одно и то же.

Допустим, нужно по числу x определить его абсолютную величину: вывести x, если x > 0, и -x иначе. Программа должна вести себя по-разному в зависимости от входных данных — значит, линейной структуры недостаточно.

{% keyline %} Условие отвечает на вопрос «истина или ложь», и по ответу программа выбирает, какую ветку выполнить. {% endkeyline %} {% program %} x = int(input()) if x > 0: print(x) else: print(-x) {% inputdata %} -273 {% endinputdata %} {% endprogram %}

Условная инструкция if состоит из условия, которое заканчивается двоеточием, и блока инструкций под ним. Блок выполняется, если условие истинно. Слово else («иначе») с двоеточием задаёт блок на случай, когда условие ложно.

{% snippet 'Синтаксис условной инструкции' %} if условие: блок, если условие истинно else: блок, если условие ложно {% endsnippet %} {% warning %} Отступы в Питоне — часть синтаксиса, а не оформление. Без отступа программа не запустится с ошибкой IndentationError. Внутри блока отступ должен быть одинаковым: используйте 4 пробела. Табуляцию лучше не использовать — редакторы подставляют её по-разному, и код ломается при копировании. {% endwarning %} {% endsection %} {% section "Неполное ветвление" %}

Слово else можно опустить. Такая конструкция называется неполным ветвлением и используется, когда действие нужно выполнить только при определённом условии: {% program %} x = int(input()) if x < 0: x = -x print(x) {% inputdata %} -273 {% endinputdata %} {% endprogram %}

Здесь x = -x выполнится только если x < 0, а print(x) выполнится всегда — она стоит вне блока.

Это отличие от других языков важно: в Си или Паскале блоки выделяются словами begin/end или фигурными скобками, в Кумире — нц/кц. В Питоне граница блока задаётся отступом, поэтому print(x) выше относится к внешнему уровню, а не к if.

{% endsection %} {% section "Операторы сравнения" %}

Условие чаще всего строится на операторах сравнения. Каждый из них возвращает логическое значение: True или False.

{% table 'Операторы сравнения' %} ОператорСмыслПримерРезультат <меньше3 < 7True >больше3 > 7False <=меньше или равно7 <= 7True >=больше или равно3 >= 7False ==равенствоa == bTrue, если значения равны !=неравенство2 * a != bTrue, если значения различаются {% endtable %} {% warning %} Самый частый баг в проверках — один знак = вместо двух. Один = присваивает значение (x = 0), а == сравнивает (x == 0). Условие с одиночным = всегда истинно, потому что непустое присвоенное значение считается True. {% endwarning %}

Условие (x * x < 1000) означает «значение x * x меньше 1000». Цепочки сравнений в Питоне работают как в математике, без дополнительных операторов:

{% snippet 'Цепочка сравнений' %} 1 <= x <= 10 # то же самое, что (1 <= x) and (x <= 10) {% endsnippet %} {% tip %} В большинстве других языков цепочку пришлось бы записать как 1 <= x and x <= 10. В Питоне это работает напрямую и читается так же, как в школьном учебнике. {% endtip %} {% endsection %} {% section "Тип данных bool" %}

Сравнение возвращает значение типа bool. У него всего два значения — True (истина) и False (ложь). Преобразования в обе стороны работают ожидаемо и используются на практике:

{% table 'Преобразования bool' %} ВыражениеРезультатПочему int(True)1истина считается единицей int(False)0ложь считается нулём bool(0)Falseноль — ложь bool(42)Trueлюбое ненулевое число — истина bool('')Falseпустая строка — ложь bool('0')Trueстрока '0' непустая {% endtable %} {% note %} Последняя строка таблицы — ловушка, на которой спотыкаются чаще всего. Строка '0' не пустая, поэтому для bool она истина, хотя при переводе в int() даёт ноль. «Нулевое» для разных типов — разные вещи. {% endnote %} {% endsection %} {% section "Логические операторы" %}

Иногда нужно проверить сразу несколько условий. Например, чтобы число n было чётным, проверяют (n % 2 == 0) — остаток от деления на 2 равен нулю. Если оба числа n и m должны быть чётными, условия нужно объединить оператором and.

Проверим, что хотя бы одно из чисел a и b оканчивается на нуль: {% program %} a = int(input()) b = int(input()) if a % 10 == 0 or b % 10 == 0: print('YES') else: print('NO') {% inputdata %} 15 40 {% endinputdata %} {% endprogram %}

А вот условие «a положительное, а b неотрицательное» записывается двумя способами:

{% snippet 'Отрицание или перенос в условие' %} if a > 0 and not (b < 0): print('OK') if a > 0 and (b >= 0): print('OK') {% endsnippet %} {% tip %} Второй вариант предпочтительнее: он не переписывает b < 0 в b >= 0 наоборот. Такие переносы легко перепутать, а условие с прямым сравнением проще проверить глазами. {% endtip %} {% endsection %} {% section "Каскадные условные инструкции" %}

Когда вариантов больше двух, цепочка if / elif / else читается лучше, чем глубокая вложенность. Условия проверяются по очереди, выполняется блок первого истинного, а если все ложны — блок else.

Сравним вложенное ветвление и каскад на одной задаче: определить, в какой четверти координатной плоскости находится точка (x, y).

{% program %} x = int(input()) y = int(input()) if x > 0: if y > 0: # x > 0, y > 0 print("Первая четверть") else: # x > 0, y < 0 print("Четвертая четверть") else: if y > 0: # x < 0, y > 0 print("Вторая четверть") else: # x < 0, y < 0 print("Третья четверть") {% inputdata %} 2 -3 {% endinputdata %} {% endprogram %}

Внутри условных инструкций допустима любая инструкция, в том числе другая условная. Вложенные блоки имеют больший отступ — например, 8 пробелов. Тот же результат даёт каскад:

{% program %} x = int(input()) y = int(input()) if x > 0 and y > 0: print("Первая четверть") elif x > 0 and y < 0: print("Четвертая четверть") elif y > 0: print("Вторая четверть") else: print("Третья четверть") {% inputdata %} -5 7 {% endinputdata %} {% endprogram %} {% note %} В комментариях к строкам выше мы записали, в каких случаях выполняется каждая ветка. Комментарий начинается с символа #, и весь текст до конца строки интерпретатор игнорирует. Такие пометки помогают не потерять смысл условия, когда программа разрастается. {% endnote %} {% tip %} Каскад читается слева направо и останавливается на первом совпадении, поэтому условия в нём выгодно писать от частных к частным. Иначе широкое условие в начале перехватит всё, и более точные проверки ниже просто не выполнятся. {% endtip %} {% checklist 'Что мы теперь умеем' %}
  • Проверять условие и выбирать одну из двух веток
  • Оставлять else, если он не нужен
  • Сравнивать значения шестью операторами
  • Объединять условия через and, or, not
  • Записывать цепочки сравнений вроде 1 <= x <= 10
  • Выбирать из нескольких вариантов через elif
